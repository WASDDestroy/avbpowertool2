# 国际化（i18n）

AVBPowerTool2 中本地化字符串的工作原理，以及如何新增本地化字符串。

## 工作机制

AVBPowerTool2 使用 Python 标准库 `gettext`，并由一个小型封装模块 `avbpowertool/presentation/i18n.py` 提供便捷接口。

关键设计约定：

- **msgid 是稳定的点分 key，不是英文句子。** 每个可翻译字符串都有一个形如 `read_image_info.title` 的标识符。英文 `.po` 文件将该 key 映射到英文文本，其他语言将同一 key 映射到各自的文本。
- **英文 `.po` 文件是事实源。** `avbpowertool/locale/en/LC_MESSAGES/avbpowertool.po` 必须包含所有 key 的条目——即使英文本身就是回退语言。覆盖率检查（`check_l10n`）正是以它为基准对比其他语言。
- **`.mo` 文件是构建产物。** 它们已被 gitignore。`init_i18n` 在启动时自动编译 `.po -> .mo`（当 `.mo` 缺失或比 `.po` 旧时）。
- **翻译只发生在 presentation 层。** domain 和 application 层返回纯数据；只有 CLI/TUI 代码调用 `_()`。

## 文件布局

```
avbpowertool/locale/
  en/LC_MESSAGES/
    avbpowertool.po    <- 事实源（提交到 git）
    avbpowertool.mo    <- 编译产物（gitignore，自动生成）
  zh/LC_MESSAGES/
    avbpowertool.po
    avbpowertool.mo
```

当前语言持久化在 `settings.json` 中（`language` 设置项，默认 `en`）。`bootstrap.py` 启动时读取它并调用 `init_i18n(language)`，加载匹配的翻译目录并回退到英文。用户在 TUI 中通过 **设置 > 修改设置 > 语言** 切换语言，新语言在下次启动时生效。

## 新增一个字符串

### 第 1 步：选定 key

使用点分、按功能划分的 key。命名约定：

| 模式 | 用途 | 示例 |
|---|---|---|
| `node.<route>.name` / `node.<route>.description` | 导航标题/描述（`resources/navigation.json` 引用它们） | `node.read_image_info.name` |
| `<feature>.title` | TUI 视图的屏幕标题 | `read_image_info.title` |
| `<feature>.<what>` | 功能内的消息、提示、错误 | `read_image_info.no_images` |
| `<feature>.field.<name>` | 格式化输出行 | `read_image_info.field.path` |
| `settings.*` | 设置界面（跨功能共享） | `settings.saved` |

key 一经发布便不可更改——视图、navigation.json 和翻译文件都引用它们。

### 第 2 步：在英文 `.po` 中添加条目

`avbpowertool/locale/en/LC_MESSAGES/avbpowertool.po`：

```po
# Read Image Info
msgid "read_image_info.results_title"
msgstr "Image Info Results"
```

条目之间空一行；每个条目上方用 `# 注释` 按功能分组（文件按功能分节组织——请遵循现有分组）。

### 第 3 步：在其他语言 `.po` 中添加相同条目

相同 msgid，翻译后的 msgstr——例如 `avbpowertool/locale/zh/LC_MESSAGES/avbpowertool.po`：

```po
msgid "read_image_info.results_title"
msgstr "镜像信息结果"
```

如果漏掉某个语言，`_()` 的回退逻辑会让该语言直接显示 msgid（即点分 key）——请务必填写所有语言文件。「检查翻译」功能（设置 > 检查翻译，或 `check_l10n()`）会精确列出某个语言缺失的 key。

### 第 4 步：在 presentation 代码中调用

```python
from avbpowertool.presentation.i18n import _

# 普通字符串
message_screen(stdscr_c, _("read_image_info.title"), lines)

# 格式化字符串：msgstr 中可以包含 {占位符} 字段
lines.append(_("read_image_info.field.path", value=img.image_path))
```

`_()` 接受 `str.format()` 关键字参数，因此形如 `"  路径：{value}"` 的 msgstr 会在调用时被填充。占位符缺失或多余时不会抛异常，而是原样保留。

### 第 5 步：运行

`.mo` 文件会在应用下次启动时自动重新编译（基于文件 mtime）。如果改动没有生效，删除 `.po` 旁边的旧 `.mo` 再重启即可。

## 占位符与格式化

- 占位符放在 **msgstr** 中，而不是 msgid：msgid 是 key（`read_image_info.field.path`），msgstr 才是文本（`"  路径：{value}"`）。
- 使用命名占位符（`{value}`、`{count}`），并作为 kwargs 传给 `_()`。
- 各语言的语序不同；命名占位符允许翻译者调整语序。代码中的示例：`_("settings.saved", key=..., old=..., new=...)`。

## 规则与限制

`i18n.py` 中的 `.po -> .mo` 编译器刻意保持精简。在此限制下：

- **不支持复数形式**（`msgid_plural`/`msgstr[n]`）和**消息上下文**（`msgctxt`）。措辞时避免依赖复数，或在翻译文本之外处理计数。
- **多行条目**仅支持连续的引号续行；避免内嵌 `\n` 之类的复杂情形——宁可每行输出一个 msgid。
- **绝不在 `domain/` 或 `application/` 中调用 `_()`。** 这两层必须与语言环境无关；在渲染时才翻译。
- **绝不在 TUI/CLI 代码中硬编码用户可见字符串**——全部走翻译目录，覆盖率检查才能跟踪。（`app.py` 中存在少量遗留的原始字符串 msgid，如 `_("Exit")` / `_("Back")`；新代码必须使用点分 key。）
- 翻译缺失时用户看到的就是 msgid——这也是 key 应当具有可读性的原因之一。

## 检查翻译覆盖率

两种等价方式：

- **TUI：** 设置 > 检查翻译——列出当前语言缺失的 key（以英文文件为基准），并显示英文默认文本。
- **API：** `check_l10n(language)` 返回缺失条目的 `{msgid: 英文默认文本}`。

## 新增一门语言

1. 创建 `avbpowertool/locale/<code>/LC_MESSAGES/avbpowertool.po`，写入标准头：

   ```po
   msgid ""
   msgstr ""
   "Content-Type: text/plain; charset=UTF-8\n"
   "Language: <code>\n"
   ```

2. 翻译所有 msgid（可参照 `zh/LC_MESSAGES/avbpowertool.po` 的结构；目前它与英文文件逐条对应）。空文件或缺失文件是允许的——所有字符串会回退到 msgid——但发布时应提供完整文件。
3. 在 `avbpowertool/infrastructure/persistence/settings_repository.py` 的 `SETTING_DEFS` 中注册语言选项：

   ```python
   "language": {
       "type": "choice",
       "label_key": "settings.language",
       "options": {
           "en": "settings.option.language.en",
           "zh": "settings.option.language.zh",
           "<code>": "settings.option.language.<code>",  # 新增
       },
       "default": "en",
   },
   ```

4. 在所有 `.po` 文件中添加对应的 `settings.option.language.<code>` 条目。
5. 无需构建步骤——`init_i18n` 会在首次运行时编译 `.mo`。

## 测试

- `tests/integration/test_bootstrap_i18n.py` 覆盖语言解析逻辑：应用持久化设置、显式参数优先、缺失设置时默认 `en`。
- 为已有视图的字符串添加测试时，断言应针对 msgid（如 `read_image_info.title`）而不是翻译后的文本——测试运行在默认目录下，不能依赖具体翻译。
